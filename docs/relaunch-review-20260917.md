## 指摘・対応

### R1: Web依存ライブラリのセキュリティ更新

Next.js 16.2.2に対するcriticalを含む監査指摘を確認。
16.3.5へ更新し、React・Nodeとの互換性と全画面を再検証する。
SheetJSはnpm配布が旧版のため公式配布0.20.3を利用する。
画面生成用CLI shadcnは開発依存へ移す。

- [Next.js公式アドバイザリー](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4)
- [SheetJS公式配布](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/)

### R2: 担当者ロールの権限範囲

`firm_advisor`は設計上「割り当てられた顧問先のみ操作」だが、追加された機能の一部が
tenant単位の権限に登録され、顧問先割当を確認する前に許可される。回帰テストと修正を実施する。

### R3: 既存デモseedの用途

既存seedは開発環境向けであり、事務所管理者の作成を含む。
外部説明・研修には、既存データへ触れない専用の作成処理と専用テナントを用意する。

## 修正・検証の進捗（未公開）

- R1: Next 16.3.5 / SheetJS 0.20.3、互換更新と限定overrideを適用。本番監査は critical 0 / high 0 / moderate 4 / low 0。残る4件はNest coreのSSEフィールド注入とその依存伝播。同サービスには`@Sse`ルートがなく、この経路は未使用。Nest major更新は別途移行検証が必要。[公式アドバイザリー](https://github.com/nestjs/nest/security/advisories/GHSA-36xv-jgw5-4q75)
- R2: 担当外アクセス6ケース・停止スタッフ1ケースを再現し修正。停止事務所、旧割当一覧、顧問先作成時の他事務所スタッフ指定も確認・修正。
- R4: Cookie優先のJWT認証と、Bearerヘッダーだけで免除していたCSRF判定の不一致を修正。
- R5: MF推移表に当月がないとき、累計PLを単月に書く経路を削除。BSはレポート日付の月へ保存。初期取込も同じ同期処理に統一し、会計年度はMFの期間情報を採用。
- R6: 設定の再同期がステータスのみ更新する実装を、実際のMF取込/kintone読込に変更。
- R7: 借入の帳簿照合をMFレポートと同日時点の返済予定表で計算し、照合日を表示。照合日が不明なら差額を断定しない。
- APIルート201件を棚卸し。JWTなしはlogin/OAuth callback/healthのみ。他はJWT + PermissionGuard、またはサービスで所属・担当を検証。
- デモ仕訳・PL/BS/推移表を実装。全仕訳の貸借、56か月のBS、月次PL合計、現預金、2025年上期・下期/2026年上期の源泉納付後0円を検証。
