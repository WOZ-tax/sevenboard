# 源泉集計：納付後残高レビュー

## 使い方

源泉所得税集計の「納付後残高レビュー」で、集計年の上期・下期を選び、「納付後残高を確認」を実行する。確認日は変更できる。

- 1〜6月分：6月30日残高と7月10日までの納付を照合。
- 7〜12月分：12月31日残高と翌年1月20日までの納付を照合。
- 初期の確認日が土日の場合は翌平日にする。祝日・個別の期限延長・納付日のずれは確認日を変更して扱う。
- 確認日が未来なら当日（日本時間）までの仕訳を使う。半期が終了していない場合は「集計期間中」と表示する。

納期の特例を適用している顧問先向け。給与・退職金・一定の士業報酬が対象であり、一般の業務委託や原稿料等を自動的に特例対象とはしない。制度・期限の出典：[国税庁 No.2505](https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2505.htm)（2026-09-15確認）。

## 照合方法

源泉所得税の勘定科目・補助科目ごとに、MF試算表の半期末残高と、半期終了後の貸借明細を照合する。預り金全体を0円と判定する機能ではない。

```text
確認日の源泉預り金残高 = 半期末残高 − 納付額 ＋ 翌期の新規徴収額 ＋ その他増減
納付後の対象期分残高   = 確認日の源泉預り金残高 − 翌期の新規徴収額
半期末の集計との差額   = 半期末残高 − 源泉集計額 − 期中の年末調整・還付等
```

- 年末調整の追加徴収はプラス、還付はマイナス。納付確認期間の調整は帰属期を要確認にする。
- 住民税・社会保険は除外する。親科目と補助科目を重複加算しない。
- 集計との差額があれば、繰越残高・期中納付・計上漏れなどを要確認として残す。期首残高を0円と仮定しない。
- 補助科目ごとの残高がすべて0円で、集計と残高も一致し、取得不足や分類の曖昧さがない場合だけ「残高0・一致」にする。異なる補助科目のプラス・マイナスを相殺して一致にしない。
- 税額が0円のデータも、MFに残高行がないケースと区別する。対象の動きがなければ「対象データなし」とする。
- 納付は、源泉科目の借方と十分な現預金の貸方があり、摘要に納付の根拠がある仕訳から抽出する。補助なし・振替のみなどは自動算入せず、要確認にする。

照合明細では仕訳日、番号、分類、科目、増減額、摘要を確認できる。確認日残高は半期末残高から仕訳を積み上げた帳簿上の値であり、納付書の提出・受理や銀行の支払結果を直接確認したものではない。

## データ取得・アクセス

`GET /organizations/:orgId/withholding-tax/review?year=2026&half=1&checkDate=2026-07-10`

- 既存のJWT認証・`org:withholding_tax:read`権限で顧問先を制限する。
- MFの会計期間で仕訳の取得範囲を分割。未払の支払月推定を検出するため直前月から読み、翌年1月も対象にする。
- 会計年度の識別子はMFのメタデータを使う。欠落期間、取得打切り、失敗、不正な仕訳、試算表の期間不一致、補助科目の欠落・重複は一致判定を保留する。
- 顧問先・集計年・半期・確認日をクエリの単位にする。条件変更中・再取得中・取得エラーでは古い一致結果を表示しない。明示的な再実行はキャッシュ済みの条件でも再照合する。
- DBスキーマ変更、会計仕訳・納付情報への書き込み、納付処理は行わない。

## 検証

- `npm test -w apps/api -- --runInBand withholding-tax`：60ケース。既存集計、納付不足・過大納付、年末調整、翌期分、科目間相殺、欠落データ、年度またぎ、日付検証、HTTP経由の顧問先権限を含む。
- API/Webのビルド、変更したWebファイルのESLint。
- ブラウザー：正常・不足・過大・要確認・エラー、明細展開、確認日・年・半期・顧問先の切替、狭い画面での表示。架空データを使用し、実際の会計データには書き込まない。
