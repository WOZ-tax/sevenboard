# ロカベンの未保存データを取得失敗と判定する不具合

## 原因

期別入力がまだ保存されていないと、feature-state APIのサービスは`null`を返す。
NestのExpressアダプターはこの戻り値を空のHTTP 200レスポンスとして送信するため、
Webの`response.json()`が失敗していた。MF側の取得が成功しても比較表示・入力を止めてしまう。
顧問先共通のロカベン状態にも同じ問題があった。

## 修正

- ロカベン状態とfeature-stateのGETは、未登録時もJSONの`null`を明示的に返す。
- 既存の`レコード | null`形式、顧問先・テナントの権限確認と保存処理は維持する。
- 実際の読み込み失敗は、MFデータと保存済み入力を分けて案内する。
- 保存済み入力の読み込み失敗時は編集を停止し、その入力だけを再取得できるようにする。
- 閲覧で空のレコードを書き込む処理は追加しない。

## 再発防止

実際のNestアプリとHTTPリクエストを使い、未登録時の本文が空文字ではなく
`null`になることを回帰テストする。変更前は2エンドポイントとも空本文で失敗することを確認。
保存済みの0・null、認証と顧問先の分離、DB障害を未登録として扱わないことも確認する。
画面検証では、同じコントローラー・サービスを動かしたローカルAPIの応答本文を
未保存ケースに利用する。DBだけを架空データに置換し、空本文の見落としを防ぐ。
